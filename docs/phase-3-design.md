# 阶段三设计：模板浏览与制作入口

状态：阶段三已完成。本文先于实现建立，现已同步实际代码、设计取舍与验收结果。

更新日期：2026-11-02。依据：[任务清单](requirements-and-task-list.md)、[接口文档](api.md)、[前端规范](standards/ts-coding-rules.md)。

## 1. 目标与边界

用户在浏览器选择演示身份、浏览模板、上传图片并提交制作。收到任务 ID 后，页面显示受理回执，解除提交状态，允许继续创建任务。

本阶段包括分类筛选、模板卡片与详情、身份切换、上传预览／替换／移除／重试、输入校验、任务提交和异常恢复。完整历史、多任务状态轮询、结果展示及刷新后的任务跟踪留在阶段四。基础响应式和键盘操作随页面实现，整体视觉打磨留在阶段五。

后端已有 17 个 HTTP 操作和六张表，本次未修改数据库或 HTTP 协议。后续出现协议缺口时，先同步本文和接口文档，再修改实现。

## 2. 页面与布局

沿用题目截图的暗色画廊、顶部身份入口和制作分区。真实内容使用已有四个原创模板与 SVG，不复制题目品牌、积分、会员或视频功能。

| 页面 | 路径 | 分区与职责 |
| --- | --- | --- |
| 模板列表 | `/`，可选 `category` 查询参数 | 顶部产品与身份区；标题和分类导航；四列模板画廊；加载、空列表、失败反馈 |
| 模板制作 | `/templates/[id]` | 返回列表与标题；左侧模板封面／要求；右侧上传表单和提交回执 |

桌面内容宽度上限 1280px，左右留白相同。列表四列、24px 间隔；平板两列，手机一列。制作页两列，窄屏堆叠；页面负责列宽与滚动，功能组件只控制自身内容。没有历史数据的阶段不放空白历史面板。

主色使用中性黑灰，封面承载主要色彩，主操作采用浅绿色。正文使用系统中文无衬线字体，不下载外部字体；标题约 28px，正文 14–16px。按钮可聚焦、可用键盘操作，上传位使用实际文件输入和明确标签。

界面检查参考 `design-taste-frontend` 的 True-black flat 方向（seed 189348452）。保留题目截图的无侧栏结构和浅绿主操作，覆盖工具默认的 T 形侧栏和白色按钮；系统中文字体也优先于工具字体建议。原因是本项目只有模板列表和制作两个主要页面，额外侧栏没有导航内容。

列表回答“选择哪个模板”，制作页回答“还需准备哪些图片才能提交”。模板封面和按模板数量生成的上传位是页面的主要内容。公开封面说明为模拟样例，避免让用户以为结果已经合成。

## 3. 前端组织与依赖

沿用 Next.js 16.4.3、React 19.3.1、TypeScript 5.9.3、ESLint 9.39.5。新增开发依赖 `@playwright/test` 1.64.1，版本已核对 npm 元数据及官方 Docker 文档；测试镜像使用同版本 `mcr.microsoft.com/playwright:v1.64.1-noble`。锁文件随安装更新。

本阶段使用 React 局部状态与身份 Context，不新增客户端业务状态库或 UI 组件库。TanStack Query 的任务轮询用途仍在阶段四评估。CSS 使用全局设计变量与按功能组织的 CSS Modules。

```text
frontend/
  src/app/                         路由入口、全局布局、错误边界
    templates/[id]/page.tsx
  src/features/
    identity/                      身份请求、会话状态、身份控件
    templates/                     模板请求、列表与详情
    creation/                      上传位、提交表单、请求归属与受理回执
  src/shared/
    api/                           HTTP 错误及响应边界校验
    ui/                            页面间复用的反馈组件
  tests/                           浏览器行为测试，测试素材与接口夹具
  playwright.config.ts
docs/phase-3-design.md              本文
```

接口返回值在请求函数内从 unknown 校验为可信类型。页面不直接导入演示 JSON，不将用户素材或任务存入 localStorage。分类由 URL 表达，避免额外维护筛选状态副本。

公开模板与分类由 Next.js 服务端组件在请求时读取 Java，首屏直接包含模板内容；读取禁用缓存，不参与构建时预取。路由 loading／error 承载导航等待与错误恢复。身份和个人写入由浏览器通过同源接口完成，Next.js 不执行制作逻辑或直接访问数据库。

## 4. 身份与请求归属

初始化读取 `/api/session`，401 表示尚未选择身份。演示用户列表单独读取，失败时显示重试入口。身份切换和退出串行执行，期间禁止个人写入。会话失败不静默假装切换成功；写入结果不确定时重新读取当前会话后才恢复操作。

2026-11-03 身份控件改用自定义选择器，替代原生 select。保留 `demo-identity` 焦点入口、演示身份标签和原会话接口。菜单使用 combobox／listbox／option 语义，方向键与 Home／End 移动，Enter／空格确认，Tab 确认并移出，Esc 或点击外部取消；当前身份以淡雾蓝背景和勾选图标标记。鼠标点击不显示外扩描边，键盘操作使用贴边 1px 焦点提示。切换期间禁用操作，身份版本变化后旧菜单失效。交互参考 [WAI 选择型组合框](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/)，未增加组件库依赖。

身份作用域带递增版本。开始切换、退出、发现会话失效或外部身份变化时，旧作用域立即失效，清理制作表单与回执。异步回调只有在用户、模板及操作仍一致时才能写入当前界面。

窗口重新获得焦点时检查会话；检查失败时暂停个人写入并提供重试。模板浏览仍可使用。关闭、取消请求和服务端取消不是同一件事：已经受理的任务继续执行。

## 5. 上传与提交状态

每个上传位使用互斥状态：空、上传中、成功、失败。成功状态包含服务端素材 ID；失败状态保留所选文件，允许主动重试。预览使用本地 Object URL，替换、移除和卸载时释放。

选择文件先检查模板 MIME 和大小；后端负责真实内容校验。每个上传位只上传一个文件。上传位的序号决定 assetIds 顺序。替换／移除先使原操作失效并取消请求，迟到结果不能恢复旧素材。

提交按钮只在已确认身份、所有上传位成功且没有提交请求时启用。提交期间锁住当前素材编辑，防止请求快照与界面不一致；用户仍可离开模板或切换身份。使用同步请求占用标记防止连续点击产生重复请求。

| 提交结果 | 界面行为 |
| --- | --- |
| 202 | 显示当前模板、任务 ID 与受理时状态；保留已上传素材，允许明确点击“再次制作” |
| 202 且任务已调度失败 | 仍显示任务 ID，明确说明受理时已失败，不能显示成制作成功 |
| 确定的参数错误 | 保留素材，显示可修正的原因，允许用户修正后提交 |
| 401 | 清理旧作用域，提示重新选择身份 |
| 网络异常、5xx 或成功响应无法解析 | 提示“提交结果未确认，任务可能已创建”，不自动重发；再次创建由用户主动操作 |

回执是当前表单中的最近一次提交快照，不是历史或实时状态。不启动轮询，不将 QUEUED 固定解释为任务当前仍在排队。更换素材后清除旧回执，切换模板或用户后销毁表单。

## 6. 执行顺序与证据

按行为执行 TDD：先增加一个能表达需求的浏览器测试并确认失败，再实现该行为；之后再推进下一个行为。安装、构建、测试和服务运行均在容器内完成。

| 顺序 | 工作 | 完成证据 |
| --- | --- | --- |
| 1 | 文档、路由与布局骨架 | 本文落盘；桌面和手机布局骨架检查 |
| 2 | 身份与模板浏览 | 浏览、分类、详情、无效模板和身份切换行为测试 |
| 3 | 上传与校验 | 数量限制、预览、替换、移除、失败重试；事件控制的迟到上传测试 |
| 4 | 提交与回执 | 重复点击只发一个创建请求；成功后可再次制作；请求失败恢复 |
| 5 | 隔离与退出 | 切换用户／模板后旧响应不进入当前表单；401 清理；卸载取消 |
| 6 | 联调与文档 | 真实 Java／MySQL 浏览器流程、lint、类型检查、构建和三种宽度截图 |

网络边界替身仅用于制造失败、延迟及不同响应顺序，不能代替真实后端联调。并发场景使用事件闸门，不用固定等待猜测完成时间。真实联调使用隔离测试数据库与文件目录，不清空演示库。

## 7. 验收与维护

- 用户从列表进入任一模板，按 1／2／3 张要求完成真实上传并获得任务 ID。
- 无效文件、上传未完成和数量不足时不能提交；错误可修正。
- 用户、模板或素材改变后，旧响应不能覆盖当前内容。
- 提交成功与提交结果不确定有不同文案；再次制作是明确动作。
- 手机可完成主要操作，键盘可到达身份、模板、文件选择和提交入口。
- lint、类型检查、生产构建和关键浏览器测试通过；记录实际联调与截图检查结果。
