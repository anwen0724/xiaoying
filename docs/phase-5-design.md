## 3. 初稿与版式约束

沿用暗色、绿色主操作、现有字体与素材。模板库保持分类加图片网格。制作页保持左侧说明与上传、右侧记录；窄屏依次堆叠。个人历史保留现有导航和网格。

初稿只在既有区域内完善功能：说明区采用较小封面配合素材要求，保留完整封面；上传区补齐错误描述与键盘焦点；任务记录区避免恢复未完成时误报空历史；加载界面按页面分区展示。不得删除题目要求的信息来缩短页面。

初稿验证完成后冻结区域顺序、页面宽度、制作双栏比例、响应式切换点、网格规则及路由。此后的 UI 修改应对应 Taste 问题编号。不应新增整页主题、侧栏、装饰区域或重排整个页面。

## 4. Taste 与 Impeccable 流程

### 4.1 Taste 评审

评审只输出以下四类及具体位置：对齐、对比、层级、间距。每项包含页面、状态、视口、组件或选择器、可见问题和局部修改边界。没有问题的类别注明未发现，不凑数量。

评审材料使用已完成的初稿截图和真实浏览器测量。新手空状态、错误和混合任务均保留，不能以占位记录掩盖空状态。

### 4.2 三次固定版式比较

初稿为 V0。随后运行三次局部修正与检查，保存 V1、V2、V3 的差异、截图和测量。三版共用同一套区域顺序与响应式规则；只调整被点名选择器内的字号、颜色、对齐或间距。没有证据需要继续修改时，保留参数并复查，不制造差异。

每次使用相同视口、固定视觉样例、固定时间、已加载字体和图片。比较：信息完整性、操作可达性、溢出、焦点可见性，以及主区域尺寸是否稳定。选择问题已解决、跨屏稳定且改动最小的一版；最后一版不自动成为定稿。

Impeccable 只执行 Taste 点名的局部修正。其默认全页优化、重新选风格或扩展设计系统的步骤不适用于本任务。

## 6. 现状与实施记录

阶段四已交付完整制作流程、多任务、个人历史和恢复。阶段五开始时，说明封面较高；上传移除／重试按钮消失后的焦点没有显式去向；输入仅关联错误文案，没有关联素材要求；历史第一页为空时尚未等待 active 完成；全站加载界面共用模板列表骨架。本阶段已修复这些问题。

结果图片重试后，焦点移至同一预览区域；历史、active 与状态重试后，焦点移至记录标题。所有操作都由用户触发，不在后台查询完成时移动焦点。模板库标题改为 h1 → h2，跳转正文目标可以接收焦点；未新增对话框。

上传输入通过 `aria-describedby` 关联格式、大小及错误，通过 `aria-invalid` 表示失败。历史与 active 都读取完成、且没有任务或不可访问记录时才显示空历史。制作页和历史页各自提供加载界面。

## 7. 三轮比较与定稿

[Taste 评审](phase-5-ui-review.md) 仅记录四类问题。Impeccable 修改限于 T-01 至 T-03：`TaskCard` 阶段段落的 class，以及 `tasks.module.css` 中的基线对齐、卡片自身高度和阶段文字样式。

| 版本 | T-01 对齐 | T-02 阶段文字 | T-03 卡片高度 | 结果 |
| --- | --- | --- | --- | --- |
| V0 功能初稿 | flex 默认顶部对齐 | 12px，辅助色 | 随整行拉伸 | 作为评审基线 |
| V1 | baseline | 14px，正文色 | align-self: start | 三视口通过，选为定稿 |
| V2 | 同 V1 | 15px，正文色 | 同 V1 | 三视口通过；与 16px 标题字号较近 |
| V3 | 同 V1 | 13px，正文色 | 同 V1 | 三视口通过；与 12px 元信息差距较小 |

三版的主区域测量全部与 V0 相同：1440px 下内容宽 1280px，制作双栏为 360px／896px，间距 24px。768／390px 均维持单列。三版均无水平溢出，单图桌面提交按钮底边为 878.27px，在 900px 视口内。选择 V1 的依据是字号层级更清楚；三版均通过稳定性检查，不宣称其他版本出现功能失败。

保留网格行序和行高计算后，短卡片下方仍可能有行内留白。这是保留版式的取舍；没有改成瀑布流，也没有把后续任务向上重排。

每版保存 15 张固定截图：模板库、制作、历史、空历史和读取失败各三个宽度。使用同一组四状态任务、固定时刻、加载完成的字体与图片。V1／V2／V3 的 CSS 参数副本、截图和 `layout-comparison.json` 位于 `artifacts/phase-5/`；定稿回归截图在 `final/`，真实提交截图在 `live/`。这些生成文件不纳入 Git。

可复现截图命令（已有依赖与后端镜像时）：

```sh
docker compose --profile browser up -d --wait frontend-dev
docker compose --profile browser run --rm -e UI_REVIEW_VERSION=review browser-test npm test -- ui-layout.spec.ts
```

该命令记录当前源码。比较历史参数时，仅调整上表点名的局部参数，不覆盖其他源文件。
