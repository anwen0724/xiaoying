# Java 开发规范

适用于本项目新增和修改的 Java 代码。现有代码在对应任务中逐步对齐，不因引入本文而全仓库格式化或重构。具体业务行为以 [阶段二设计](../phase-2-design.md)、[库表设计](../database-design.md) 和 [接口文档](../api.md) 为准。

## 1. 命名与格式

- 包名小写；类、接口、枚举和 record 使用大驼峰；方法、参数和变量使用小驼峰；常量使用全大写加下划线。
- 名称表达业务含义，避免难懂缩写和含义模糊的命名。
- 使用 4 个空格缩进，左花括号与声明同行；条件、循环语句使用花括号。
- 方法和逻辑段之间适当空行；长参数列表、调用链和条件换行，不将多个处理步骤压在一行。
- 使用编辑器的 Java 格式化功能保持上述格式，清理无用 import；不顺带重排无关文件。

## 2. 可读性与注释

- 注释使用中文，补充命名和类型无法直接表达的契约、边界与原因。
- 业务 Service 接口添加 Javadoc，说明职责和调用约定。参数、返回值、空值、异常或副作用影响调用方式时，应明确说明。
- 实现方法可继承接口说明，只补充实现特有的约束，不复制整段接口注释。
- 类、枚举和 record 的职责、取值或使用边界不直观时添加 Javadoc；名称和结构已清楚的简单类型不强制重复说明。
- 方法内部只为非直观的业务规则、事务边界、并发控制、失败中断和资源释放添加原因说明，不按每条语句或每个步骤机械加注释。
- 字段的单位、取值范围或空值含义不直观时添加说明，DTO 和 Entity 同样适用。
- 简单 getter/setter、名称明确的局部方法和直接字段转换不强制添加注释。
- 注释与代码同步修改，不保留过期说明或注释掉的旧实现，不把语句直接翻译成中文。

例如，方法的说明应让调用者理解实际行为：

```java
/**
 * 读取当前用户的任务记录，不触发后台执行。
 * 任务执行失败时仍返回记录，由响应中的失败字段说明原因。
 *
 * @param userId 从服务端会话取得的当前用户 ID
 * @param taskId 要查询的任务 ID
 * @return 当前用户可见的任务记录
 * @throws BusinessException 任务不存在或不属于当前用户
 */
TaskResponse getTask(String userId, String taskId);
```

示例用于展示注释形式，具体类型和错误映射按实现及接口契约确定。

## 3. 类、方法与分层

- 一个类承担清晰职责，一个方法围绕一项明确操作展开；过长方法按有意义的处理步骤拆分，避免多层嵌套。
- 优先使用清晰命名和直接的控制流程；不为简单逻辑增加无必要的抽象、接口或包装层。
- Controller 处理 HTTP 参数、身份取得及响应；Service 处理业务校验、规则和事务；Mapper 处理数据库读写。
- 业务 Service 采用接口与实现类分离，接口放在 `service`，实现放在 `service/impl`；调用方依赖业务接口。解析器、校验器等辅助组件不强制增加接口。DTO 表达接口数据，Entity 表达持久化数据。
- 工具适配器通过 Service 调用业务，不直接操作 Mapper；HTTP 和工具入口复用相同业务规则。

## 4. 校验与异常

- 接口边界校验格式、必填项和长度；Service 校验用户权限、对象归属、状态及业务约束。
- 用户身份从服务端认证或可信执行信息取得，不信任请求或模型提供的所有者字段。
- 明确省略字段、null 和空值的含义；集合、状态及数值边界按接口契约处理。
- 业务失败使用明确的错误码和异常，在接口或工具边界统一转换；不吞异常，不将失败伪装为成功或空结果。
- 对外不暴露堆栈、SQL 和内部配置信息；内部记录诊断所需的异常原因。

## 5. 事务与日志

- 明确事务范围，相关业务数据和记录需要保持一致时共同提交；失败整体回滚。
- 涉及并发修改时按 spec 使用版本校验、锁或唯一约束，避免读后写覆盖；锁顺序保持一致。
- 事务内避免模型调用等耗时网络操作；事务提交后的失败不能被描述为数据已回滚。
- 使用项目日志框架，记录必要的业务标识、处理结果和失败原因，不使用 System.out 或 printStackTrace 代替日志。
- 不打印凭据或无关的私人内容；同一异常避免在各层重复输出完整堆栈。

## 6. 测试与执行

- 功能和修复采用 TDD：先写能体现预期行为的失败测试，再实现和重构。
- 测试覆盖业务行为、边界、权限、失败及必要的并发情况，不测试私有实现细节或机械覆盖 getter/setter。
- 运行与改动相关的测试及必要构建检查，记录真实结果和未执行项；模型替身测试与真实模型验证分开说明。
- 本规范通过开发和代码审查执行。是否启用 Checkstyle、Spotless 等自动检查，以实际构建配置为准；采用本文不自动引入插件或依赖。
